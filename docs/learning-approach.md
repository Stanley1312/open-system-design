# Learning Approach

## Suggested workflow

1. Open a version directory and read its README.
2. Read CHALLENGE.md before looking at the solution.
3. Implement the missing behavior in starter/.
4. Exercise successful flows, validation boundaries, and failure cases.
5. Compare your work with solution/.
6. Use the demo and design notes to inspect behavior that is difficult to see
   from code alone.
7. Write down the current limitations before moving to the next version.

## Philosophy

A component should be introduced because a concrete limitation requires it, not
because it appears in a typical system design diagram.

The code favors human readability, traceable request flows, and observable
behavior over production completeness. Each version deliberately leaves some
problems unsolved so the reason for the next version remains clear.

AI may help with UI work, repetitive tasks, review, and documentation. The core
learning still comes from understanding the flow, writing the solution, testing
assumptions, and being able to explain the decisions.
